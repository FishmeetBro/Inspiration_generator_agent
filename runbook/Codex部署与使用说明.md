# Codex 部署与使用说明

## 1. 部署目标

把这套多 Agent 资产包放入 Codex 后，你应该得到一个“主 Agent 负责调度，5 个子 Agent 负责专职分析”的新品灵感系统。

## 2. 最小部署单元

至少需要以下 3 层：

1. 主 Agent 提示词
2. 子 Agent 提示词
3. 共享数据契约

如果你只是要先跑通流程，这 3 层就够了。

## 3. 推荐部署方式

### 方式 A：纯提示词编排

适合先验证逻辑。

- 给主 Agent 绑定 `00_中枢调度主Agent_SystemPrompt.md`
- 把 5 个子 Agent 当作独立角色调用
- 每一轮输入统一传 `task_brief`
- 每一轮输出统一回写共享 JSON 结构

### 方式 B：提示词 + 本地表格 / 数据库存储

适合进入半生产状态。

- 用表格或数据库保存：
  - 新领域机会池
  - 爆款拆解池
  - 特征库
  - 专利风险黑名单
  - 历史输出方案
- 每轮运行前加载历史高频特征和失败记录

### 方式 C：提示词 + 外部 API

适合正式上线。

- 平台趋势数据 API
- 评论抓取 API
- 专利检索 API
- 物流计费规则库
- 成本 BOM 估算模块

## 4. 建议输入模板

```json
{
  "request_id": "REQ-20260610-001",
  "user_goal": "为亚马逊和抖音寻找适合桌面收纳赛道的可专利新品灵感",
  "target_market": ["douyin_cn", "amazon_global"],
  "workflow_hint": "hybrid",
  "constraints": {
    "categories": ["桌面收纳", "DIY配件", "居家小件"],
    "exclude_categories": ["带电产品", "大件家具"],
    "max_material_delta_pct": 15,
    "min_margin_cn": 30,
    "min_margin_global": 45,
    "small_parcel_only": true,
    "avoid_electronics": true,
    "avoid_patent_dense_shapes": true
  },
  "seed_keywords": ["磁吸", "可拆卸", "模块化", "透明收纳", "车载兼容"]
}
```

## 5. 建议输出策略

每次运行建议控制在：

- 3 到 5 个 top candidates
- 3 到 10 个 dropped candidates

这样既能保留足够探索空间，也不会让结论过于发散。

## 6. 建议评分维度

你可以让主 Agent 为每个候选增加一套 100 分制评分：

- 需求强度：25 分
- 差异化：20 分
- 场景成立度：15 分
- 成本可控性：15 分
- 物流友好度：10 分
- 专利与合规安全度：15 分

## 7. 首轮上线建议

第一阶段不要追求全自动，先做到：

- 主 Agent 自动选工作流
- 子 Agent 统一输出结构
- 主 Agent 自动终审与淘汰

第二阶段再补：

- 持久化特征库
- 黑名单更新
- 月度复盘
- 反馈闭环

## 8. 你后续最值得继续补的模块

- 特征库真实字段设计
- 专利相似度打分规则
- 成本估算公式
- 物流箱规规则表
- 平台限制词与禁售词库

## 9. 如何判断这套系统是否跑通

如果主 Agent 能稳定做到下面 5 件事，就说明已经基本成型：

1. 能自动识别应该走哪条工作流
2. 能调用不同 Agent 并合并结果
3. 能淘汰明显无效方案
4. 能输出结构统一的候选产品方案
5. 能解释每条方案的商业逻辑与风险
